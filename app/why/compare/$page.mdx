## 一画面版

| | create-react-app | Vite + React | Next.js | Bun | uf |
| --- | --- | --- | --- | --- | --- |
| 状態 | React が非推奨化（2025 年 2 月） | 保守中 | 保守中 | 保守中 | 0.0.0-alpha プレリリース |
| 言語 | TS or JS | TS or JS | TS or JS | TS or JS | **Flow** |
| component / hook / renders / match | Babel プリセット | Babel プリセット | Babel プリセット | なし | **ネイティブ** |
| dev サーバーとビルド | webpack | Vite | Turbopack（or webpack） | bun build | Vite 8 |
| テストランナー | Jest | 自分で追加 | 自分で追加 | bun test | uf test |
| フォーマッタ | 自分で追加 | 自分で追加 | 自分で追加 | なし | バイナリ内 |
| リンタ | ESLint（同梱） | 自分で追加 | 自分で追加（`next lint` は 16 で削除） | なし | バイナリ内 |
| 型チェッカー | tsc | tsc | tsc | tsc | uf check（Flow） |
| 本番サーバー | — | — | next start | Bun.serve を自分で書く | uf start / アダプタ / --compile |
| 設定ファイル | なし → eject で全部 | ツールごとに 1 つ | ツールごとに 1 つ | ツールごとに 1 つ | **uf.config.js だけ** |

この表の 2 行がほぼすべてを決めます。**TypeScript を書いているなら、構文の行はあなたにとって無価値で、他のすべての行はダウングレード**です。数年のデプロイ実績のある本番サーバーが必要なら、その行はまだ Next.js のものです。

## 負ける行を先に読む

| uf が負けるもの | 相手 | どれくらい |

| デプロイの成熟度 | Next.js | 7 アダプタと `--compile` は実装済みで、CI は生成された Cloudflare Worker を Wrangler のローカルランタイムで起動する。しかし実戦デプロイされたサーバーアダプタはなく、serverless はストリームをバッファする（#956） |
| Server Components | Next.js | Flight ペイロードで描画し、Server Component はブラウザに届かない。しかしサーバー関数を prop で渡すこと、インライン `"use server"` クロージャ、ネイティブフォームの progressive enhancement はない（#1038） |
| 型付きエコシステム | 全員 | Flow libdef のないパッケージは `any` |
| インストールできること | 全員 | npm にはプレリリースとして、プロジェクトが必要とするクロージャだけ。`@uniflowed/std` はまだ pending（#710） |

## create-react-app と比べて

CRA は「正直な祖先」です。ビルドを 1 つの依存の裏に隠したオールインワン。React は 2025 年 2 月に非推奨化し、フレームワークかビルドツールを推奨しました。

**uf が受け継いだもの:** 形。1 コマンド、コピーする設定なし、判断を 1 つもしないうちに動くプロジェクト。

**uf が失敗から学んだもの:** eject の崖と一方通行の扉、エコシステムのすべてのアップグレードを直列化する単一パッケージ、そして「ビルドを解決して止まった」こと。uf は 1 つ目に連続体（eject なし）で、2 つ目に「実装ではなくオーケストレーションを所有する」で、3 つ目に「フレームワークでもある」で答えています。3 つ目だけが未完です。

**CRA にあって uf にないもの:** それを前提にした 10 年分のチュートリアルと、安定版・公開済み・インストール可能なソフトウェアで動くという事実。

## Vite + React と比べて

もっとも近く、もっとも敵対的でない比較です。uf の dev サーバーとビルドは Vite そのもの（`vite: "^8.2.2"`）で、JSON プロトコルで運転しています。バンドル性能は行になりません。同じバンドラだからです。

**uf が足すもの:** パイプラインに Babel を一切含まない Flow の React 構文。`vite.config.ts` + テスト設定 + フォーマッタ設定 + リンタ設定の代わりの 1 ファイル。ビルドと同じ構文木を読むテストランナー・フォーマッタ・リンタ・型チェッカー。

**素の Vite が持っていて uf が捨てるもの:**

- TypeScript、そしてそれと共に npm 上のあらゆる型付きパッケージ
- 「ビルドツールであり、それ以上ではない」こと。素の Vite はルーター、アクションプロトコル、レンダラー、テストランナー、フォーマッタを決めません
- `vite preview` の直接所有
- `if (import.meta.hot)` をガードとして書くこと
- 好きな Vite バージョン。uf はテスト済みの系列に固定します

変わらないのは逃げ道です。`uf.config.js` の `vite` キーは uf の生成物の上にマージされ、`plugins` は普通の Vite プラグインの配列です。

## Next.js と比べて

最大のギャップであり、率直に言う価値のあるものです。

| 機能 | Next.js | uf（現在） |
| --- | --- | --- |
| ファイルシステムルーティング、ネストレイアウト | ○ | ○ |
| 描画前のデータ読み込み | ○ | `loader` export |
| ルートハンドラ | ○ | uf dev / preview / start とサーバーアダプタで ○。static アダプタは名指しで拒否 |
| Server Components / Server Actions | ○ | Flight ペイロードで RSC、呼び出し可能な export アクション。prop としてのサーバー関数、インラインアクション参照、ネイティブフォームの progressive enhancement はなし |
| ストリーミング、Suspense 境界 | ○ | Node / Bun / Deno / container / edge で HTML ストリーミング。static は待ち、serverless はバッファ |
| ISR、キャッシュ、再検証 | ○ | opt-in のルートキャッシュと fetch キャッシュ、時間ベースとオンデマンドの再検証、`isr` によるバックグラウンド再生成。`ppr` モード名は予定のみ、data / action キャッシュは拒否 |
| ミドルウェア | ○ | サーバーターゲットではルート解決前に走る。static では拒否 |
| HTTP QUERY | × | ルートハンドラが `QUERY` を export でき、`@uniflowed/fetch` が送る |
| 画像最適化 | ○ + リクエスト時の最適化 | ビルド時のみ。AVIF なし、lossy WebP なし、リクエスト時エンドポイントなし |
| フォントのセルフホスト | ○（ダウンロードとサブセット） | import したフォントをセルフホスト、metric 一致のフォールバックを計算、`subset: "ranges"` で script ごとに分割。プロバイダからのダウンロードはしない |
| エラー境界 | ○ | `$error.js`。`unauthorized()` / `forbidden()` / throw が 1 つの `RouteError` として届く |
| デプロイアダプタ | 多数 | node / bun / deno / container / edge / serverless / static + `--compile`。同一の応答をするテストはあるが、実デプロイの証明はない |

**uf にあって Next.js にないもの:** Flow の推論でチェックされる Flow の React 構文。同じバイナリ・同じ木を読むフォーマッタ・リンタ・テストランナー（Next.js 16 は `next lint` を削除し、`next build` はもう lint しません）。ランタイムを内蔵した単一実行ファイル（`output: 'standalone'` は Node を必要とするディレクトリを書きます）。そして「ルート単位でサーバーが省略可能」なフレームワーク。

**CVE になった Next.js の失敗に対して uf がしていること:** サーバーアクションの id はビルドの HMAC、引数はコンストラクタ名のタグを持たない閉じた JSON 文法、エンドポイントは `Origin` が `Host` と一致しない呼び出しを拒否、どのミドルウェアが走るかはリクエストパスで決まりヘッダでは決まらない。`docs/security.md` が各決定を CVE-2024-34351 や CVE-2025-29927 などに対応付けています。

**結論:** 今期、本番でリクエストごとに描画しなければならない TypeScript アプリを作っているなら Next.js を使ってください。uf はその形を今も動かせますが、「退屈な答え」をまだ獲得していません。

## Bun と比べて

Bun と uf の重なりは機能表が示唆するより小さいです。Bun はパッケージマネージャ・バンドラ・テストランナーを持つ**ランタイム**、uf はランタイムの上で動く**ツールチェーン**で、Bun もその 1 つです。

**Bun が勝つところ（計測済み）:** 同じスイートを `bun test` は 58 ms、`uf test` は warm 125 ms / cold 429 ms（50 ファイル、1,000 テスト、2,000 アサーション、8 コア M3、25 ラウンドの中央値）。約 2.2 倍。理由は構造的で、Bun はランナーをエンジンに書き込んで 1 プロセスで動かし、uf はワーカープロセスを起動して 1 ワーカー 1 ファイルで隔離し、起動コストをワーカーごとに払います。

**同じ比較で uf が勝つところ:** `vitest run`（1,310 ms）より約 10 倍速く、Node.js でも Bun でも動き、Flow が動きます。`bun test` に `component` / `hook` 構文はありません。

**パッケージ管理:** uf は実装しません。`uf install` などはプロジェクトのマネージャ（Bun 含む）を検出して実行し、そのマネージャに該当コマンドがなければそう言います。ライフサイクルスクリプトは入口で拒否。Bun のインストーラは完成品（リゾルバ、グローバルキャッシュ、ロックファイル形式）で、uf のはあなたのマネージャの前に置かれたポリシーです。意図的に。「リゾルバを書けば uf がエコシステムの全アップグレードの関所になる」からです。

## で、どれを選ぶか

- **TypeScript を書いていて今期本番へ:** サーバーが要るなら Next.js、要らないなら Vite。uf はここで競っていません。
- **TypeScript を書いていて設定ファイルの数が不満:** [Vite+](/why/vite-plus)。
- **Flow を書いている、または書きたい:** uf。そして今のところ他に選択肢がありません。それが uf の存在理由です。
- **静的サイトを作っている、好奇心がある、早期採用者でよい:** uf はこの（公式）サイトを `uf build` でビルドしています。
