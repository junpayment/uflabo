## uf は Vite の競合ではない

もっともよく逆に思い込まれる点なので、ここから始めます。

**uf の dev サーバーは Vite です。本番ビルドも Vite です。** uf は設定を解決し、Vite に何を渡すか決め、JavaScript ホスト上で起動し、JSON プロトコルで運転します。Vite のプラグインエコシステムは動き続けます。本当に Vite だからです。`uf.config.js` の `plugins` は Vite プラグインのリストです。

Vite を置き換えることは、1 つのことを変えるためにエコシステムでもっともテストされたバンドラパイプラインを作り直すことを意味しました。uf が変える 1 つのこととは、**Vite がモジュールを見る前に、そのモジュールに何が起こるか**です。

## 違い

| | Vite+ | uf |
| --- | --- | --- |
| 中心の言語 | TypeScript | Flow |
| 理解する React 構文 | JSX と TypeScript | component, hook, renders, match, Flow enum |
| 変換 | Oxc | Meta の Flow パーサー → Hermes の lowering → React Compiler クレート → oxc |
| バンドラ / dev サーバー | Vite と Rolldown | Vite |
| 設定 | vite.config.ts | uf.config.js（Flow で書く） |
| フレームワーク | 自前のものはなし | ルーター、ストリーミング SSR、Server Actions、デプロイアダプタ、--compile |
| タスク | `vp run`（ワークスペース横断、キャッシュつき） | `uf run`（dependsOn グラフ、並列上限、宣言した入力でキャッシュ、`--why` で理由表示） |
| 依存 | `vp install` などをあなたのマネージャの上で | `uf install` などをあなたのマネージャの上で。依存の install スクリプトは `uf pm approve-builds` で名指ししない限り off |
| パッケージのバイナリ | `vp exec` / `vp dlx` がダウンロードして実行 | `uf exec` / `ufx` はプロジェクトがインストール済みのものだけ。取得は `--yes` 必須 |
| エージェント | `vp config` で連携設定 | `uf mcp`: stdio 上の 8 ツール |
| 成熟度 | 資金とチームのある製品 | 0.0.0-alpha、全ページにそう書いてある |

最初の行が、ほとんどの読者にとって答えを決めます。

## 「TypeScript ファースト」が Flow を書く人に課すもの

TypeScript ファーストのツールチェーンは Flow を拒否しません。単にその経路を持たないので、自分で作ることになります。それはパイプラインに Babel を戻すことです。型を剥がすプリセット、`component` / `hook` を理解するプラグイン、React Compiler 用のもう 1 つ、そして同じ構文をテストランナー・リンタ・フォーマッタにそれぞれの設定で説明し直す。

その 1 つ 1 つが、2 つのツールがあなたのコードの意味について食い違える場所です。そして食い違いは無関係な場所に現れます。テストは通るがビルドが失敗する、フォーマッタが整形した構文をリンタが拒否する。

## Vite+ にあって uf にないもの

機能表より有用なので、はっきり書きます。

- **チーム、会社、サポート契約。** uf は安定性保証のないプレリリースです。3 年後も動いていなければならない仕事のためにツールチェーンを選ぶなら、この差が判断のすべてです。
- **TypeScript エコシステム。** npm 上のすべての型付きパッケージ、すべてのエディタ連携、すべての質問へのすべての答え。
- **大規模モノレポのツーリング。** `vp run` はワークスペースのパッケージ横断でタスクを走らせます。uf は 1 プロジェクトのタスクグラフをキャッシュつきで走らせ、`uf run#member` で他メンバーのタスクに届きますが、1000 パッケージのリポジトリの近くに行ったことはありません（#967）。

## uf が正しい選択になるとき

- React を書いていて、Flow が React のために持つ構文が欲しい: 引数リストから推論される props、チェッカーが強制する hook のルール、特定の子を要求できるコンポーネント、網羅的な match、本物の enum。
- 同じことを 6 つのツールに教えるより、1 バイナリと 1 設定ファイルの方がいい。
- プレリリースと、「Flow 型のないパッケージは誰かが書くまで `any`」というエコシステムに耐えられる。

TypeScript を書いているなら、**Vite+ の方が uf がなり得る何よりも良い答え**です。公式ドキュメントもこのページであなたを説得しようとはしていません。

## 併用できるか

部分的に、今日でも。uf は標準の Vite を運転するので、Vite プラグインを使っているプロジェクトはそのまま使えます。合成できないのは変換です。モジュールは Flow か TypeScript のどちらかで、uf のパイプラインは Flow のものです。またコマンドは積み重なるのではなく重なります。両方に dev サーバー、テストランナー、リンタ、フォーマッタ、タスクランナー、パッケージマネージャのフロントエンドがあるので、プロジェクトはそれらのためにどちらか 1 つを走らせます。
