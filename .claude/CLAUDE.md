## サブエージェントのモデル選択方針

Agent ツールでサブエージェントを起動するときは、タスクの性質に応じて `model` を使い分ける。

| タスクの種類 | モデル | 例 |
|---|---|---|
| 設計・計画・アーキテクチャ判断・難しいデバッグ | `opus`（ハイパフォーマンス系） | 実装方針の策定、複数ファイルにまたがる変更の設計、トレードオフの検討、根本原因の調査 |
| 葉っぱの実装タスク | `sonnet` | 設計が決まった後の個別ファイルの実装、テスト追加、既存パターンに沿った修正 |
| 本当に些細な作業 | `haiku` | 単純な検索、ファイル一覧の確認、typo 修正、フォーマット調整、定型的な置換 |

### 運用ルール

- 判断が必要な上流の仕事ほど高性能モデル、手を動かすだけの下流の仕事ほど軽量モデルに寄せる。
- 迷ったら一段上のモデルを選ぶ（sonnet か haiku で迷ったら sonnet）。
- 設計フェーズで opus が出した方針を、sonnet の実装エージェントにプロンプトで明示的に渡すこと。
- `fork` は親のモデルを継承するので、この使い分けは fork 以外のサブエージェントに適用する。
