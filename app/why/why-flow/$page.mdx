## 一段落で言うと

Flow はここ数年、React を記述するためだけに存在する構文を増やしてきました。`component` と `hook` の宣言、render 型、パターンマッチ、enum。他の型システムはどれも持っていません。しかしそれを使うには、Babel とプリセットと React Compiler プラグインを組み、バンドラ・テストランナー・リンタ・フォーマッタにそれぞれ別の設定ファイルで同じ構文を教える必要がありました。uf はその税金を取り除くためだけに存在します。

## Flow だけが言えること

### コンポーネントは「注釈する形」ではなく「宣言の種類」

```js
component Avatar(src: string, size: number = 32, alt?: string) {
  return <img src={src} width={size} height={size} alt={alt ?? ""} />;
}
```

props の型は引数リストそのものです。シグネチャと同期させる第 2 の宣言はなく、デフォルト値は引数を宣言した場所に置かれ、prop が足りなければ呼び出し側でその引数名を含むエラーになります。他の言語では「interface、分割代入パターン、デフォルト値オブジェクト」の 3 か所が同じものを記述し、それらは食い違うことができます。

さらに、コンパイラは「これはコンポーネントだ」と直接知らされます。React Compiler は大文字で始まる名前から推測するのではなく、宣言そのものを受け取ります。

### hook のルールが型エラーになる

```js
hook useNow(interval: number): Date { … }
```

Flow はこれを、コンポーネントか別の hook 以外から呼ぶことを許しません。インストールして設定する lint ルールではなく、他のすべてをチェックしているのと同じチェッカーが出す型エラーです。React でもっともよくあるバグの一種が「規律」の問題ではなくなります。

### コンポーネントが子を要求できる

```js
component Tab(label: string) renders React.Node { … }
component Tabs(children: renders* Tab) { … }
```

`renders Tab` はちょうど 1 つ、`renders? Tab` は 0 か 1 つ、`renders* Tab` は任意個です。`<Tabs><Button /></Tabs>` はコンパイルが通りません。「この 2 つのコンポーネントは一緒にしか意味をなさない」が、ドキュメントの依頼ではなく型システムの強制になります。

### 忘れられない網羅性

```js
enum Status { Idle, Loading, Failed }

const label = match (status) {
  Status.Idle => "Ready",
  Status.Loading => "Working…",
  Status.Failed => "Failed",
};
```

enum にメンバーを足すと、それを処理していないすべての `match` がコンパイルを止めます。Flow の enum は実行時にも本物の値で、反復可能・キャスト可能・素の文字列と偶然比較できない、という点で文字列リテラルの union とは異なります。

### exact と variance がデフォルト

Flow のオブジェクト型は、指定しない限り exact です。プロパティの variance は明示的で、`readonly` は共変、`writeonly` は反変。読み取り専用 prop は「慣習」ではなく型のプロパティとして表現できます。

## Flow が言えないこと

公式ドキュメントは、上のリストより「ここ」を正直に書くことが重要だと述べています。

- **エコシステムは TypeScript のもの。** ほとんどのライブラリは `.d.ts` を出荷し、libdef は出荷しません。Flow 型のないパッケージは、誰かが書くまで `any` です。20 個の型付き依存の上に立つプロジェクトなら、これがあなたの払うコストです。
- **エディタ支援は薄い。** Flow の言語サーバーは良いものですし uf は `uf lsp` を出荷していますが、TypeScript ツーリングに取り組む人数に Flow が並ぶことはありません。
- **知っている人が少ない。** 採用、Q&A、「コントリビュータが `renders` を見たことがある確率」。すべて TypeScript 有利です。

uf はこれらで Flow が勝つとは主張しません。「型システムの仕事が JavaScript 一般ではなく React を正確に記述することなら、Flow は他に言えないことを言える。そして、あなたとそれの間に立っていたのはツールチェーンだけだった」と主張します。

## なぜプラグインではなく丸ごとのツールチェーンなのか

プラグインは問題の言い換えだからです。2 つのツールが `component` の意味について合意しなければならなくなった瞬間、それらは合意するように設定されなければならず、合意しないように設定されることもできます。静かに、テストが通ってビルドが落ちるまで。

uf は Meta 製 Flow パーサーを 1 つのバイナリにコンパイルし、すべてがその 1 本の木を読みます。「このファイルは何を意味するか」への答えが 1 つなのは、その問いの実装が 1 つだからです。`uf.config.js` が唯一の設定ファイルで Flow で書かれているのも同じ理由です。
