## 一言でいうと

uf は、**Meta 製 Flow パーサーの Rust 移植を 1 つのバイナリに埋め込み、dev サーバー・ビルド・テスト・フォーマッタ・リンタ・型チェッカーがすべて同じ構文木を読む**ようにしたツールチェーンです。名前の由来は "Unified toolchain for Flow"。

React は Flow で書かれていて、Flow には React を記述するための専用構文（`component`、`hook`、`renders`、`match`、`enum`）があります。ところが、それを使うには Babel のプリセットとプラグインを組み、バンドラ・テストランナー・リンタ・フォーマッタそれぞれに同じ構文を別々に教える必要がありました。uf はその「税金」を取り除くために作られました。

## 2 つの顔

| 顔 | 中身 |
| --- | --- |
| **ツールチェーン** | `uf dev` `uf build` `uf test` `uf fmt` `uf lint` `uf check` `uf install` `uf run` など。Rust バイナリ 1 つ、設定は `uf.config.js` 1 つ。 |
| **フレームワーク** | `app/` 配下のファイルがルートテーブルになるルーター、Server Components、Server Actions、ストリーミング SSR、ルートキャッシュ、OAuth、ロガー、ヘッドレス UI 部品、状態管理、フォーム、Effect ライブラリ、i18n、標準ライブラリ。 |

create-react-app の失敗（「ビルドを解決して止まった」ので、全員がその上に自前フレームワークを作った）を繰り返さないために、uf は最初からフレームワークでもあることを選んでいます。詳しくは [アーキテクチャ](/why/architecture)。

## パイプライン

Flow ファイルはすべて、Rust の中で次の 1 本のパイプラインを通ります。Babel はどこにもありません。

| 段階 | 担当 |
| --- | --- |
| Parse | `flow_parser` — Flow 自身が使う Meta 製パーサー（Rust 移植） |
| Lower | Hermes のパスを移植したもの。`component` `hook` `match` `enum` を落とし、型を剥がす |
| Optimize | 公式 React Compiler の Rust クレート |
| Emit | oxc — JSX 自動ランタイム、dev 時の Fast Refresh、コード生成、ソースマップ |

dev サーバーも本番ビルドもテストランナーもホスト上の Flow モジュール読み込みも、全部これを通ります。「このファイルが何を意味するか」の答えが 1 つしかないのは、その問いの実装が 1 つしかないからです。

## 何を自分で持たず、何を持つか

uf の設計原則は「**オーケストレーションは持つ、実装は持たない**」です。

- **バンドラは Vite 8。** フォークもラップもせず、JSON プロトコルで Vite を運転します。`uf.config.js` の `vite` キーは uf が生成する設定の上にマージされ、`plugins` は普通の Vite プラグインの配列です。
- **型チェックは Flow。** `uf check` は Flow の推論をそのまま走らせ、Flow の答えを報告します。uf が独自に型を判断することはありません。
- **パッケージマネージャは持たない。** `uf install` はプロジェクトの npm / pnpm / Yarn / Bun を検出して呼び、その前に「install スクリプトを拒否する」などのポリシーを挟むだけです。
- **フォーマッタとテストランナーは自前。** Flow を理解するものが存在しなかったので、ここだけは例外として自分で持っています。ただし「置き換え可能であり続ける」ことを条件にしています。

## 実行環境は 3 つに分かれる

「ランタイム」という言葉を 1 つにまとめないのが uf の特徴です。

| | 意味 |
| --- | --- |
| オーケストレーションホスト | uf 自身が動く場所。ネイティブバイナリ |
| プラグインランタイム | JavaScript プラグインが動く場所。Node.js / Bun / Deno |
| ターゲットランタイム | 成果物が動く場所。ブラウザ、ワーカー、サーバー |

普通のビルドでも 3 つは全部異なります。「ネイティブバイナリが Node.js 上の Vite を運転して Cloudflare Worker 向けバンドルを作る」という具合です。

## 現在地（2026 年 9 月）

- バージョンは **0.0.0-alpha**。安定性の保証はなく、インターフェースは予告なく変わります。
- 対応 OS は macOS と Linux（x86-64 / ARM64）。**Windows ビルドはなく**、WSL2 で動かします。
- JavaScript ホストは Node.js（デフォルト）、Bun、Deno 2.8 以降。
- 7 種類のデプロイアダプタと単一バイナリ生成は実装済みですが、**uf 自身のパイプラインで実際のプラットフォームにデプロイされた実績はまだありません**（#956）。
- 公式ドキュメントのサイト自体が `uf build` でプリレンダリングされた uf プロジェクトです。

## このサイトの構成

公式ドキュメントの構成をほぼそのまま踏襲しています。

- **uf を選ぶ理由** — 採用判断のための議論と、その代償
- **セットアップ** — インストール、最初のプロジェクト、エディタ、チュートリアル
- **アプリを作る** — ルーティングから Web Vitals まで、アプリが行うこと 1 つにつき 1 ページ
- **動かす場所** — Web デプロイ、React Native、ターミナル UI
- **ツールチェーン** — コマンド 1 つにつき 1 ページ、CI、エージェント、移行
- **リファレンス** — コマンド、設定、パッケージ、標準ライブラリなど
