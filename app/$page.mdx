## 30 秒でわかる uf

```sh
curl -fsSL https://setup.uniflowed.dev | sh   # バイナリを 1 つ入れる
uf new my-site                                # プロジェクトを作る
cd my-site && uf install                      # 依存を入れる（npm/pnpm/yarn/bun を裏で呼ぶ）
uf dev                                        # Vite ベースの dev サーバー
```

- **言語は Flow。** `component` / `hook` / `renders` / `match` / `enum` という、React を記述するために Flow が追加した構文を、Babel なしでネイティブに扱います。
- **1 バイナリ、1 設定ファイル。** `vite.config.ts` も `babel.config.js` も `.eslintrc` も `tsconfig.json` も `vitest.config.ts` もありません。あるのは `uf.config.js` だけです。
- **バンドラは Vite そのもの。** uf は Vite をフォークせず、Rust 側で設定を組み立てて Vite を「運転」します。Vite プラグインはそのまま使えます。
- **フレームワークでもある。** ファイルシステムルーティング、Server Components、Server Actions、ストリーミング SSR、7 種類のデプロイアダプタ、単一実行ファイルへのコンパイルまで含みます。

## 1 ページだけ読むなら

[uf がやらないこと](/why/not-do) を読んでください。公式ドキュメントも同じことを言っています。「1 か月使ってから気づく制限は、その 1 か月を無駄にする」ので、意図的な「拒否」と単なる「未実装」を issue 番号つきで先に並べたページです。TypeScript を書いていて Flow に移る理由が特にない人には、[Flow と TypeScript](/why/flow-vs-typescript) の「どう決めるか」の節が答えになるはずです。
