このページは 2 つのリストです。**uf が意図的に拒否すること**と、**まだできていないこと**。後者には issue 番号が付きます。「issue のない未実装は願い事に過ぎない」からです。

## 拒否（決定であり、issue で閉じることはない）

### eject を持たない

`uf eject` はなく、`uf config --write` も「有効な Vite 設定を印字してコピーできるフラグ」もありません。実際にはそれが eject になるからです。create-react-app はゼロ設定と完全カスタマイズの間に崖を作り、その底に一方通行の扉を置きました。uf は扉を連続体で置き換えます。

```
convention  →  configuration  →  provider replacement  →  raw provider API
```

各段階は前より小さく、どれもロックしません。Vite プラグインが 1 つ必要なプロジェクトは Vite プラグインを 1 つ足すだけで、ビルドシステムを相続しません。

### バンドラを所有せず、フォークしない

dev サーバーと本番ビルドは Vite（`vite: "^8.2.2"`）で、uf は JSON プロトコルで運転します。Vite にない挙動が必要なら、答えはプラグインかアップストリームへの変更であり、フォークではありません。これが第 1 のレッドラインで、理由があって第 1 です。ベンダリングしてパッチした Vite は永遠に uf のものになるからです。

**使える帰結:** Vite ができることは uf プロジェクトでもできます。uf のリリースを待たずに。

### あなたのコードを型チェックしない

Flow がします。`uf check` は Flow 自身の推論を走らせ、Flow の言うことを報告します。uf が型推論を再実装すれば、あなたのプログラムについての「第 2 の意見」が生まれます。それこそがこのツールチェーンが取り除くために存在する失敗です。

### Flow がすでに名付けたものに新しい名前を付けない

ファイルは `@noflow` で「素の JavaScript だ」と言います。uf は `check.exclude` リストを足しません。すでに答えのある問いへの第 2 の答えを、読者が見ていない場所に置くことになるからです。

### npm のライフサイクルスクリプトを実行しない

`uf install` は、install 時のライフサイクルスクリプト（パッケージマネージャがインストール中に勝手に実行するフック）を宣言する manifest を、何も取得する前に拒否します。

```
error: package manifest /…/my-site/package.json declares install-time
       lifecycle scripts (postinstall), which run code during an install;
       move that automation to uf tasks in uf.config.js
```

対象は npm の `preinstall` `install` `postinstall` `prepublish` `preprepare` `prepare` `postprepare` `prepack` `postpack` `dependencies` と、pnpm の `pnpm:devPreinstall`。install 時スクリプトは「リポジトリを clone しただけのマシン」に対するリモートコード実行の経路です。プロジェクトの自動化は `uf.config.js` の `tasks` に置きます。

install が実行しないスクリプトは拒否されません。`create-expo-app` や React Native テンプレートが書く `start` `android` `ios` は、人が `npm run ios` と打ったときだけ走るので、uf は「実行しない」と 1 行言うだけです（以前はあらゆる scripts を拒否していましたが、#992 でフックだけに絞られました）。

依存自身の install スクリプトも走りません。uf が運転するすべてのマネージャにデフォルトで `--ignore-scripts` を渡します。読んで納得した依存は `uf pm approve-builds` で名指しでき、pnpm / Bun / Yarn 2+ ではマネージャ自身が読むフィールドに記録されます。npm と Yarn 1 にはそのリストがないので、uf は「全パッケージ一括承認」を静かに意味する承認を提供する代わりに、そう言います。

### ルーティング可能なアドレスを静かに bind しない

`uf dev --host` は、`dev.allowedHosts` が空の間は、プロセスを 1 つも起動する前に起動を拒否します。allow-list のない `0.0.0.0` の dev サーバーは、あなたのソースツリーのファイルサーバーです。uf は決してあなたの代わりに `*` を書きません。

### 再現できないものをフォーマットしない

`uf fmt` はタグ付きテンプレート内の GraphQL をフォーマットしますが、Prettier と正確に一致できない場合（ドキュメント内の `#` コメント、制御文字を含む文字列、128 段を超えるネスト）はテンプレートをバイト単位でそのまま残します。Relay のテストスイートの 1,138 個の graphql テンプレートのうち、1,092 個で Prettier を再現し、46 個を辞退します。全部コメントが理由です。「だいたい正しい」はフォーマッタが許されるものではありません。

### ネイティブのアセットコーデックを足さず、フォントのメタデータを推測しない

`uf assets` は純 Rust ライブラリでデコード・エンコードします。C コンパイラもネイティブコーデックのインストールもリリース時のシステム依存もなしに、1 つのツールチェーンとして出荷できる代わりに:

- AVIF なし（実用的な純 Rust の経路は AV1 エンコーダで、副作用として届くべき規模ではない）
- lossy WebP なし（エンコーダは C ライブラリの libwebp）
- サブセット済みフォントの WOFF2 出力なし（WOFF2 は読めるが、エンコーダは出荷しない）
- import からのテキストサブセットなし（テキストは 1 つの用途に属し、import は Vite のクエリ構文しか運べない）
- フォントファイル名からの font-weight / font-style 推測なし

#997 がこれらを「未実装」から「拒否」に移した issue です。

### フレームワーク非依存ではないし、そうなろうともしない

uf は Flow と React です。プロジェクトの `.js` `.jsx` `.mjs` `.cjs` は uf が変換します。`node_modules` 下のサードパーティ依存は対象外（Flow ソースを出荷する `@uniflowed/*` を除く）。**アプリ内の TypeScript ファイルは Flow モジュールではありません。** フォーマッタは Biome に渡し、uf の他の部分は読みません。

### 2 つのテストファイル間でプロセスを共有しない

`uf test` は各ワーカーに一度に 1 ファイルだけ渡します。プロセスを共有する 2 ファイルはグローバルを共有し、「単独では通るが隣に別ファイルがあると落ちる」スイートはランナーが生み得る最悪の失敗です。実時間のコストはあります。ワーカーをコアごとに起動し、各ワーカーはテスト API を読み込んでから動くので、これが `bun test` との差の出どころです。隔離を外して取り戻すつもりはありません。

### 「誰がやった？」に沈黙で答えない

`uf inspect --json` は解決済みの設定とルートテーブルを印字します。`uf explain <command>` は dev / build / test / fmt / lint / check の各段階のプロバイダ（どのバイナリが何をするか）を名指しします。説明できない段階は存在すべきでない段階です。

## 拒否と未実装の見分け方

拒否には `docs/red-lines.md` に書かれた理由があり、どの issue も閉じません。未実装には issue 番号と担当者がいます。

どちらもない境界（このページに理由がなく、リンクする issue もない）にぶつかったら、それはこのページの欠陥であり、そう報告する価値があります。
